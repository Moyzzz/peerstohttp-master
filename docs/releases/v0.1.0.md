# v0.1.0

首个正式版。本版本给 `/content` 补上了缺失的"种子回收端"：种子不再只增不减，而是按引用计数共享、空闲后自动断开连接并移除记录。同时修复了三个会导致内存与连接长期占用的实际缺陷。

## 修复

- **反复访问不同视频后内存只涨不降。** 此前每请求一个新的 info hash 都会在内存里永久留下一个种子记录，连带它的分片表、请求顺序表和 peer 连接。现在请求结束后会按空闲时间自动回收。
- **播放器关闭或拖动进度条后，后台仍长期占用连接与内存。** 现在最后一个请求结束后会先断开该种子的全部 peer 连接，空闲一段时间后连记录一起移除。
- **客户端断开后请求长期挂住，导致种子永远无法回收。** 读取没有跟随请求的取消信号，客户端离开后服务端仍在等待分片到达。现在读取会在客户端断开时立即结束。
- **播放器请求间隙被立即断连，导致续播和拖动变慢。** 播放器"缓冲满了就中止请求、稍后再发新 Range"是正常行为，此前每次间隙都会把 peer 连接全部断掉再重连。新增的断连宽限期解决了这个问题。
- **`/list` 在拿不到元数据时无限等待。** 现在按超时返回 `504`，不再让请求永久挂起。

## 优化

- **启动不再预加载历史种子。** 数据库里的录制只作为元数据缓存，首个请求命中时才创建种子，内存占用不再随历史访问量增长。
- **`/content` 与 `/list` 共享同一种子实例。** 同一视频的清单请求与播放请求不会重复创建对象。
- **元数据缓存注入。** 已缓存的种子再次访问时直接从本地数据库注入元数据，省掉一次与 peer 的元数据交换，`info` 秒出。

## 新增启动参数

四个参数都有默认值，**原有启动命令无需修改即可生效**。

| 参数 | 默认值 | 说明 |
|---|---|---|
| `-idle-ttl` | `90` 秒 | 最后一个请求结束后，空闲多久移除该种子记录 |
| `-disconnect-ttl` | `15` 秒 | 最后一个请求结束后，空闲多久断开该种子的 peer 连接；`0` 表示立即断开 |
| `-info-timeout` | `30` 秒 | 等待种子元数据的上限，超时返回 `504`；`/content` 与 `/list` 共用 |
| `-keep-meta` | `true` | 种子被移除后是否保留本地元数据缓存；设为 `false` 可减小数据库体积，但重复访问需要重新交换元数据 |

## 升级提示

- 行为变化仅限"空闲种子会被回收"。播放、拖动、清单接口的用法与返回格式均未改变。
- 内存紧张的环境可以用 `-idle-ttl=45 -disconnect-ttl=10 -info-timeout=15` 加快回收。
- 如果播放时出现"每次缓冲间隙都重新连 peer、速度上不去"，把 `-disconnect-ttl` 调大（例如 `60`）。
- 如果拖动或切集后首字节变慢、CPU 抖动，说明种子被回收得太频繁，把 `-idle-ttl` 调大。
- 需要"重开同一视频秒出清单"就保持 `-keep-meta=true`（默认）；如果更在意磁盘占用可以关掉。

## 兼容性

- HTTP 接口未变：仍为 `/list/{json|m3u|html}/...` 与 `/content/{hash}/{path}`，无新增或废弃端点。
- 无破坏性变更：所有新增参数均有默认值；数据库格式未变，旧版留下的 `.app.bolt.db` 可直接复用。
- 新增日志（`torrent created` / `torrent idle` / `torrent dropped`）仅用于观测，不影响接口输出。
