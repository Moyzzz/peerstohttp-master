# v0.2.0

新增 `HEAD` 支持（只读本地缓存，绝不触发下载），并修复跨域请求对 `HEAD` 与 `Range` 的支持。

## 新增

- **`HEAD /content/{hash}/{path}` 可以用了。** 它只从内存或本地数据库回答"这个文件有多大、支不支持分段"，**不创建种子、不连 peer、不下载任何数据**。
- **命中来源可见。** 响应头 `X-Cache` 会告诉你答案来自哪里：

  | `X-Cache` | 含义 |
  |---|---|
  | `HIT-MEM` | 来自内存中正在使用的种子，响应时间通常 < 1 ms |
  | `HIT-DISK` | 来自本地数据库里的元数据缓存，通常几毫秒 |
  | `MISS` | 本地没有任何记录，直接返回 `503` |

- **支持 `Range` 探测。** 带 `Range` 的 HEAD 按规范返回 `206` + `Content-Range`，并给出该区间的 `Content-Length`；支持 `bytes=a-b`、`bytes=a-`、`bytes=-n` 三种写法。
- **响应头更完整。** 命中时返回 `Content-Length`、`Content-Type`（按扩展名推断）、`Accept-Ranges: bytes`、`Content-Disposition`。

## 修复

- **跨域 HEAD 请求被浏览器拦截。** 因为 CORS 的方法白名单里没有 `HEAD`，中间件对这类请求不会附加 `Access-Control-Allow-Origin`，浏览器因此判为跨域失败。
- **跨域 Range 请求的预检失败。** `Range` 不在跨域允许的请求头列表里，带 `Range` 的 `fetch` 会在预检阶段被拒。
- **跨域脚本读不到关键响应头。** `Content-Range`、`Accept-Ranges`、`X-Cache` 之前不在 `Access-Control-Expose-Headers` 里，前端无法读取。

## 行为说明

- HEAD 是**纯缓存探测**：从未访问过的 hash 会返回 `503` + `X-Cache: MISS`，即使这个种子在网络上完全可用。需要真正下载时请改用 GET。
- 元数据存在但请求路径不匹配时返回 `404`（同样带 `X-Cache`）。
- `/list` 接口与相关行为本次未改动。

## 兼容性

- 无破坏性变更：GET 的语义、状态码、Range 行为与 v0.1.0 完全一致。
- 新增的 `X-Cache` 响应头为附加信息，不影响任何既有客户端。
- 无需新增启动参数，原有启动命令直接生效。

## 升级提示

- 如果前端之前因为 CORS 报了 HEAD 相关的错误，升级后即可正常读取状态码与响应头。
- 若仍有 `credentials: 'include'` 的跨域请求失败，那属于另一类问题（`Access-Control-Allow-Origin: *` 不能与凭据同时使用），需要把允许的源改成具体域名。
